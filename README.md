# Online Shoppers — Purchase Classification

**Классификация покупательских сессий интернет-магазина на Python и scikit-learn.**

Учебный pet-проект: исследование поведения пользователей, сравнение моделей на несбалансированных данных и оценка качества на отложенной выборке. Лучший результат среди рассмотренных моделей показало настроенное дерево решений: **Average Precision — 0,693, ROC-AUC — 0,925 на test**.

[Исследование](research.ipynb) · [Датасет](data/online_shoppers_intention.csv) · [Зависимости](requirements.txt)

## Задача

По предоставленным характеристикам пользовательской сессии определить, относится ли она к классу с покупкой. Единица наблюдения — одна сессия; целевая переменная — `Revenue`: `True` означает покупку, `False` — её отсутствие.

Проект оценивает качество **офлайн-классификации по готовой таблице сессий**. Применение модели до покупки требует отдельной проверки доступности признаков на момент прогноза.

**Стек:** Python, pandas, NumPy, Matplotlib, scikit-learn, Jupyter.

## Данные

Используется [Online Shoppers Purchasing Intention Dataset](https://archive.ics.uci.edu/dataset/468/online%2Bshoppers%2Bpurchasing%2Bintention%2Bdataset) из UCI Machine Learning Repository.

| Характеристика | Значение |
|---|---:|
| Сессий в исходных данных | 12 330 |
| Признаков без целевой переменной | 17 |
| Пропущенных значений | 0 |
| Удалено полностью совпадающих строк | 125 |
| Сессий в экспериментах | 12 205 |
| Доля положительного класса после удаления строк | 15,63% |
| Обучающая / тестовая выборка | 9 764 / 2 441 |

Признаки описывают просмотры и длительность посещения страниц, показатели веб-аналитики, источник трафика, тип посетителя, устройство и календарные характеристики. Числовые коды ОС, браузера, региона и источника трафика обрабатываются как категории.

Решение об удалении совпадающих строк и связанные с ним ограничения описаны ниже.

## Как построено исследование

1. Проверены типы данных, пропуски и совпадающие строки.
2. До EDA отделены 20% данных для test: `stratify=y`, `random_state=42`.
3. На train изучены дисбаланс классов, распределения, доли нулей и корреляции.
4. Предобработка объединена с моделями в `Pipeline`: `StandardScaler` для числовых признаков и `OneHotEncoder(handle_unknown="ignore")` для категориальных, через `ColumnTransformer`.
5. Модели сравниваются на одинаковых пяти фолдах `StratifiedKFold(shuffle=True, random_state=42)`. Преобразования обучаются внутри каждого фолда. Для подбора гиперпараметров используется `GridSearchCV`.
6. Выбранная модель оценена на test; рассчитаны метрики и матрица ошибок. Test не используется для выбора моделей и проверки гипотез.

Основная метрика — **Average Precision (AP)**. Дополнительно рассчитываются ROC-AUC, Precision, Recall, F1 и Accuracy. При доле покупок около 15,6% предсказание только отрицательного класса уже даёт Accuracy около 84,4%, поэтому этой метрики недостаточно.

## Сравнение моделей

| Модель / конфигурация | Средний AP на CV |
|---|---:|
| DummyClassifier, `strategy="prior"` | 0,156 |
| Logistic Regression, базовая | 0,636 |
| Logistic Regression, L2, `C=0.01` | 0,641 |
| Logistic Regression, L1, `C=0.01` | 0,651 |
| Logistic Regression, L2, `C=0.01`, `class_weight="balanced"` | 0,643 |
| Decision Tree, базовое | 0,385 |
| **Decision Tree, после подбора гиперпараметров** | **0,695** |

CV используется для выбора конфигурации. Оценки настроенных моделей получены на фолдах, участвовавших в подборе параметров, и могут быть оптимистичными; итоговая отдельная проверка выполнена на test.

Финальная модель — `DecisionTreeClassifier` с параметрами:

```python
max_depth=5
min_samples_leaf=5
min_samples_split=2
random_state=42
```

Это лучшая **среди проверенных в проекте** конфигураций. Ансамбли и другие семейства моделей не сравнивались.

## Результаты на test

| Метрика | Значение |
|---|---:|
| Average Precision | 0,693 |
| ROC-AUC | 0,925 |
| Precision | 0,706 |
| Recall | 0,641 |
| F1 | 0,672 |
| Accuracy | 0,902 |

AP и ROC-AUC рассчитаны по `predict_proba`, остальные метрики — по стандартному `predict`. Порог классификации отдельно не подбирался: использовано стандартное правило с границей 0,5.

| Фактический класс | Предсказано: без покупки | Предсказано: покупка |
|---|---:|---:|
| Без покупки | 1 957 (TN) | 102 (FP) |
| Покупка | 137 (FN) | 245 (TP) |

Из 382 сессий с покупкой модель верно классифицировала 245. Среди 347 положительных предсказаний 245 оказались правильными. Близость AP на CV и test согласуется с полученной оценкой, но сама по себе не доказывает устойчивость на других данных.

## Основные эксперименты

В ноутбуке сформулированы шесть гипотез с количественными критериями. Ключевые результаты:

| Эксперимент | Результат |
|---|---|
| Базовая логрегрессия против базового дерева | Средний AP: 0,636 против 0,385 |
| Ограничение сложности дерева | AP вырос с 0,385 до 0,695; разрыв train–validation сократился с 0,615 до 0,049 |
| L1-регуляризация логрегрессии | Обнулены 65 из 74 коэффициентов после кодирования; AP — 0,651 против 0,641 у L2 |
| Балансировка классов в логрегрессии | Recall вырос с 0,330 до 0,746, Precision снизился с 0,757 до 0,528 |
| Добавление `AvgProductDuration` | Установленный критерий улучшения не выполнен: средний AP остался около 0,641 |
| Исключение `PageValues` из логрегрессии | Средний AP снизился с 0,641 до 0,321 на тех же фолдах |

Для L1 был задан критерий абсолютного отличия AP от L2 не более 0,01. Фактическое отличие составило около 0,011, поэтому по условиям эксперимента гипотеза подтверждена частично, хотя L1 показала более высокий AP.

Эффект балансировки относится к логрегрессии; автоматически переносить этот вывод на финальное дерево нельзя. Обнуление коэффициентов L1 исследовано отдельно и не использовано для отбора признаков финального дерева.

## Интерпретация и ограничения

- **Доступность признаков.** В CSV нет последовательности событий и временных меток, позволяющих восстановить все признаки на фиксированный момент до покупки. Офлайн-результат не подтверждает качество прогноза во время активной сессии.
- **`PageValues`.** По описанию UCI это метрика ценности страниц, связанная с транзакциями. Не подтверждено, что её значения рассчитаны исключительно по информации, доступной до прогнозируемой покупки. Это риск утечки информации из будущего, а не установленный факт. Эксперимент без признака показывает зависимость качества логрегрессии от него; он не доказывает доступность остальных признаков в онлайне.
- **Совпадающие строки.** В текущем исследовании удалены 125 полностью совпадающих строк. Однако одинаковые характеристики могут принадлежать разным сессиям; описание UCI указывает на разных пользователей. Поэтому удаление следует считать исследовательским допущением. Чувствительность результатов к сохранению этих строк не проверялась.
- **Границы оценки.** Использовано случайное стратифицированное разделение. Перенос качества на будущие периоды, другие магазины и изменившийся трафик не проверялся.
- **Бизнес-применение.** Стоимость ошибок и бизнес-порог не определены. Рост конверсии, выручки или прибыли не измерялся. Найденные зависимости не доказывают причинного влияния признаков на покупку.

Возможное развитие — оценка вероятности покупки для приоритизации помощи пользователям. Для этого нужны признаки, доступные в выбранный момент, отдельная валидация на новых данных и экспериментальная проверка эффекта вмешательства. Высокая вероятность покупки сама по себе не означает, что пользователю полезно показывать скидку.

## Запуск

Код исследования проверен на **Python 3.12.14**, pandas **2.2.3**, NumPy **2.3.5**, Matplotlib **3.10.8** и scikit-learn **1.7.2**. В `requirements.txt` указаны допустимые диапазоны версий, а не полностью зафиксированное окружение.

1. Клонируйте репозиторий и создайте окружение:

```bash
git clone https://github.com/andreym1234/online-shoppers-purchase-classification.git
cd online-shoppers-purchase-classification
python -m venv .venv
```

2. Активируйте окружение.

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Linux / macOS:

```bash
source .venv/bin/activate
```

3. Установите зависимости и запустите JupyterLab:

```bash
python -m pip install -r requirements.txt
jupyter lab
```

4. Откройте `research.ipynb`, выберите ядро созданного окружения и выполните все ячейки сверху вниз. Запускайте JupyterLab из корня проекта: загрузка CSV использует относительный путь `data/online_shoppers_intention.csv`. Датасет уже включён в репозиторий.
